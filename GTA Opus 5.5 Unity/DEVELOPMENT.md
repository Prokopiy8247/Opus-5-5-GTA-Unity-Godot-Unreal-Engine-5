# DEVELOPMENT — Port Halcyon (Unity GTA-style free-roam sandbox)

Original, missionless open-world sandbox on a ~600 × 600 m island city. Launches straight into free roam.
All 3D assets were modelled through the project's Blender MCP connection; everything else (textures, audio, UI,
world layout) is generated by project code. No downloaded/third-party asset packs are used.

## 2. How to run

* **Built games:** `Builds\PortHalcyon-Windows\PortHalcyon.exe` (Windows x64) and `Builds/PortHalcyon-macOS/Port Halcyon.app` (macOS Universal). Both start in free roam at the Palm Row safehouse. Public binaries are distributed through GitHub Releases.
* **Editor:** open the project in Unity 6000.6.0f1 → scene `Assets/GTA/Scenes/PortHalcyon.unity` (also the only scene
  in Build Settings) → Play.
* **Regenerate everything from the Blender exports** (menu `Halcyon/…` or batch):
  ```
  Unity.exe -batchmode -nographics -projectPath <project> -executeMethod Halcyon.EditorTools.Pipeline.RunAll -quit
  Unity.exe -batchmode -nographics -projectPath <project> -executeMethod Halcyon.EditorTools.Pipeline.BuildWindows -quit
  Unity.exe -batchmode -nographics -projectPath <project> -executeMethod Halcyon.EditorTools.Pipeline.BuildMacOS -quit
  ```
  `RunAll` = project settings → material library → prefabs from FBX → world scene. `PrefabsWorldAndBuild` does
  materials+prefabs+world+player build in one go. The world builder writes a coverage report to
  `QA/world_builder_report.txt` (last run: 144 buildings, 2094 props, 848 nature items, 40 interaction points,
  50 vehicle spawns, 680 pedestrian spots, 111 road segments, 11 landmarks, 0 missing asset types).
* **Automated validation run:** `PortHalcyon.exe -autotest -screen-fullscreen 0 -screen-width 1600 -screen-height 900`
  drives the real gameplay code through simulated input (`GameInput.Sim*`), writes `QA_Screens/autotest_log.txt`
  (PASS/FAIL per check with measured values, FPS) and ~65 screenshots next to the exe, then quits.
  Archived runs: `QA/Game/run*/` (logs + contact sheets).

## 4. Architecture (`Assets/GTA/Code`, namespace `Halcyon`)

* `Core/` — `GameBootstrap` (single entry point placed by the world builder; creates every runtime system and the
  player), `GameInput` (Input System facade + autotest simulation layer), `CoreTypes` (layers, damage, events, pool,
  utilities), `GameDatabase` (prefab registry ScriptableObject, `Resources/GameDatabase.asset`), `Catalogs`
  (16 weapons, 20 vehicles), `AutoTester`.
* `Player/` — `PlayerController` (CharacterController state machine: ground/air/swim/dive/ladder/cover/freefall/
  parachute/vehicle/down), `PlayerCamera` (orbit, aim shoulder cam, first person, vehicle chase cam, collision),
  `CharacterRig` (procedural animation of the 17-bone Blender rig: locomotion, aiming, driving, swimming, ragdoll),
  `CharacterAppearance` (outfits/hair/accessory variation), `Actor` (health/armour/damage), `PlayerState` (money,
  skills, garage, gear).
* `Vehicles/` — `Vehicle` base (seats, enter/exit, carjack, damage + deformation, fire/explosion, lights, siren, horn,
  audio, mods), `CarVehicle` (WheelColliders), `BikeVehicle`, `BoatVehicle` (buoyancy probes), `HeliVehicle`,
  `PlaneVehicle`, `VehicleFactory` (builds physics from the Blender `COL_*`/`WHEEL_*`/`SEAT_*` helpers), `VehicleMods`,
  `VehicleApi` (mod shop, garage).
* `Traffic/` — `RoadNetwork` (lane graph + signal phases), `TrafficManager` (moving + parked cars, despawn),
  `VehicleAI` (lane following, lights, gap keeping, turns, pedestrians, police pursuit/search).
* `AI/` — `NPCBrain` (wander, perception by sight/hearing, flee/panic/combat, drivers), `Population` (pedestrian
  spawner with simulation tiers).
* `Police/` — `WantedSystem` (0–5 stars, heat = severity × witnesses, pursuit vs search, escape timer, busted),
  `PoliceDispatch` (cars, officers, SWAT van, roadblocks, helicopter with pilot + marksmen).
* `Weapons/` — `WeaponController` (hitscan/projectiles, recoil/spread, reload, melee, throwables, attachments).
  `Combat/` — explosions/projectiles, `VFX` (particles, tracers, decals).
* `World/` — shops, activities (range, stunt jumps, street race), interactables, parachute, radio, wildlife, taxi,
  day/night + weather, street lights. `UI/` — runtime-built uGUI HUD, minimap/full map, weapon wheel, menus, phone.
  `Audio/` — every sound synthesised in code. `Save/` — JSON save/load.
* `Editor/` — `Pipeline` (settings, materials, prefabs, build), `WorldBuilder` + `WorldContent*` (terrain, roads,
  districts, props, interaction points), `GTAModelPostprocessor` (FBX import settings).

Edit-time components (`DynamicProp`, `TrafficLightProp`, `Spinner`, `Interactable`, `Ladder`, `Flapper`, `LampLight`,
`WorldData`, `GameBootstrap`) and the `GameDatabase` ScriptableObject each live in a file named after the class —
otherwise Unity serialises them as missing scripts and the player build's `level0` is corrupted (found and fixed in
segment 5).

## 6. Blender → Unity asset workflow

1. Every asset is built by `bpy`/`bmesh` code executed **through the verified MCP** (`execute_blender_code`) in the master
   file, under `GTA_UNITY/{Characters,Vehicles/{Cars,Motorcycles,Boats,Helicopters,Airplanes},Weapons,Buildings,
   StreetProps,Nature,Animals,Misc}`. Safe Mode forbids classes/lambdas/exec, so the helpers are plain functions
   (`box`, `boxr`, `cyl`, `done`, `emp`, `export`, `text_obj`; last batch kept in `Tools/blender_last_batch_code.py`).
2. Naming carries gameplay meaning: `<ID>__BODY`, `__COL_*` (collision helper, hidden), `__WHEEL_FL/FR/RL/RR`, `__SEAT_n`,
   `__DOOR_n`, `__STEER`, `__SIREN_R/B`, `__ROTOR_MAIN/TAIL`, `__PROP`, `__GEAR`, `__MOD_*` (optional body kit parts),
   `__MUZZLE`, `__GRIP`, `__TRUNK`, `__LEAF*`, `__WING_L/R`, `__SIGN`. Materials are flat-colour Principled BSDF named
   `M_*`; Unity swaps them for the shared material library by name.
3. Visual QA: Workbench renders of each asset (`QA/Blender/*.png`, contact sheets) — the MCP viewport screenshot returned
   a stale frame in this session, so renders to file were used instead.
4. Export: FBX per asset into `Assets/GTA/Generated/Models/<Category>/` (`use_selection`, `apply_scale_options=FBX_SCALE_ALL`,
   `axis_forward='Z'`, `axis_up='Y'`, triangulated, no leaf bones, root moved to the origin during export).
5. Unity: `GTAModelPostprocessor` (bake axis conversion, no cameras/lights) → `Pipeline.BuildPrefabs` (library materials,
   colliders from `COL_*` or generated, LODGroup culling, static flags, character rig components) → `GameDatabase` →
   `WorldBuilder` placement → runtime factories (`VehicleFactory`, `NPCFactory`, `AnimalFactory`).

Asset counts (143 Blender assets → 143 prefabs, ~171k triangles total): 2 rigged characters (17-bone rig, used for the
player and every NPC via outfit/hair/colour variation), 20 vehicles, 16 weapons + attachment kit, 38 buildings, 43 street
props, 14 nature assets, 9 animals, 1 shipwreck.

## 8. Known limitations

See `FEATURE_MATRIX.md` (PARTIAL / NOT IMPLEMENTED rows) and `OPUS_5.5_FINAL_REPORT.md` → "Known bugs". Highlights:
no trains/transit line, no authored keyframe animation clips (all character motion is procedural), NPC variety comes from
two base bodies, no building interiors (shops, services and the safehouse are used from their doors), the Unity editor
play mode was not used for QA (validation ran on the Windows player).
